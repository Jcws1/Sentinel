# Contract package 1.10 — local fleet policies and persistent demo outcomes

Deploy backend and frontend together. World/stream **1.9**, interactive/status **1.6**, command receipts **1.5** and checkpoint **1.6** carry D4. Scenario/review remain **1.3**, SQLite remains **4**, and stored profile speeds are unchanged. Existing tables already atomically store receipts, events, frames and checkpoints; no migration or application dependency is added. Packages 1.0–1.9 remain archived unchanged.

`behavior` is a leased selected-member command with a shared logical `order` and a `hold`, `intercept` or `patrol` policy. Intercept activation holds and establishes manual override; it does not allocate targets. A subsequent direct map request with optional `intercept: true` captures eligible authoritative hostile IDs within the disclosed 250 m intent area. Receipt operation `intercept-approach` includes frozen `targetScope`, `behaviorOrder` and per-member accepted/skipped outcomes. No field is added to legacy ordinary direct request bytes when the discriminator is absent. New reviewed Move requests also use optional top-level `order`, echoed by `movementOrder`; existing pending requests without it retain their exact shape and reconciliation.

`fleetBehavior` projects current policies, member state, assignments, held reserves, patrol routes and durable outcomes. Current assignment history is bounded to 64; older decisions remain in immutable frames and events. Accepted pairs are preserved and remaining legal pairs use distance plus stable target/member identity ordering. Targets are unique, reserves never deploy automatically, and no source step expands the accepted scope. New runs explicitly grant source `fleet-policy`/`demo-outcome` and eligible friendly binding `demo-intercept` capabilities; reading a legacy run never grants them.

`demo-mutual-loss-v1` records its 200 ms step, persisted profile speed, 250 m intent radius, 25 m contact threshold and 1 mm tolerance. Pursuit is horizontal toward the latest committed target position; supplied heights remain unchanged. A relative swept 3D contact test records pre-step frame/sequence, proposed and evaluated positions, interpolation fraction, participants, assignment/policy/command/source identities and resulting commit sequence. Both losses, asset unavailability, movement/script termination, assignment release, events, checkpoint and frame commit together before publication. No physical, sensor, vehicle or real engagement performance is asserted.

Current effective Restricted rules enforce inclusive whole-segment movement checks. Friendly rules veto pursuit/contact; Patrol uses a validated convex clockwise 10% centroid inset and straight ingress. Geometry changes/deletion hold affected patrols until explicit reapplication. Stop disarms; Return permits only eligible future script work. Restart preserves completed evidence, losses and effective boundaries, clears credentials, advances epoch, pauses and interrupts/disarms unfinished work without replay or catch-up.

Strict legacy world 1.8, status 1.5 and receipt 1.4 readers validate archived shapes before adaptation, alongside earlier readers. Stored receipt bytes, source specifications and hash guards are unchanged. Script paths are now emitted only by the shared scenario-authoring presentation context; run/recording action data and textual accounting remain intact.

Current receipt 1.5 selected-control outcomes additionally allow `UNAVAILABLE` skips. Exact bound members without movement capability do not prevent eligible members from applying behavior, Stop or Return. Missing/changed bindings still reject before mutation; all-unavailable selections return `NO_AVAILABLE_ASSETS`. Frozen receipt 1.4 readers retain their original outcome enum and exact stored bytes.
