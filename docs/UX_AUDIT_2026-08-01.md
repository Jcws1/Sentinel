# Sentinel SDTH UX and BMS Realism Audit

Date: 2026-08-01  
Scope: Current SDTH Sentinel application at `http://localhost:5173/`  
Primary viewport: 1280 x 720  
Compact viewport: 1024 x 768

## Executive assessment

Sentinel has a strong specialist-operator foundation: the map is information-rich, the sensor workspace exposes meaningful health data, the ROE workspace uses progressive disclosure, and the AI assistant clearly states its authority boundary.

The product is not yet safe or coherent enough to behave as a real BMS command surface. The main limitation is not missing visual polish. It is that the UI can hide, contradict, or visually obstruct mission-critical state and controls:

- side workspaces overlap an active decision instead of reflowing or suspending it;
- the compact breakpoint removes link, GNSS, queue, and authority information;
- some labels imply backend effects that do not occur;
- reconnect behavior can execute queued commands against a changed operational picture;
- demo/replay content is presented with the visual authority of live operational data.

The best direction is to retain the map, sensor, edge and robotic-control strengths while rebuilding the shell around a governed command lifecycle and an explicit operational-state model.

## What already works well

| Area | Positive behavior |
|---|---|
| Map and battlespace | Strong geographical context, terrain display, asset/threat visualization and selectable operational objects. |
| Mode switching | Switching away from Defense warns that pending decisions will be hidden and requires confirmation. |
| Decision evidence | The decision card exposes ROE state, sensor count, update age and civilian-buffer information near the action. |
| Sensor health | Useful source summary, freshness, throughput, delivery state and runtime sensor controls. |
| ROE information architecture | Clear overview, configuration categories, draft banner, environment selector and audit area. |
| AI authority boundary | Clearly states that the assistant is advisory and has no direct simulator, raw-device or command authority. |
| Replay concept | Timeline, mission list and decision/event separation provide a good foundation for after-action review. |
| Focus visibility | The visual focus outline is generally easy to see. |
| Reduced motion | The stylesheet includes a reduced-motion media query. |

## Severity model

- **P0 — operator risk:** can hide, misrepresent or trigger mission-relevant behavior.
- **P1 — major usability:** materially slows correct decisions or causes navigation/action errors.
- **P2 — quality and accessibility:** reduces legibility, learnability or consistency.
- **P3 — polish:** useful improvement after the operational model is sound.

## Findings

| ID | Severity | Finding | Evidence | Recommended behavior |
|---|---|---|---|---|
| UX-01 | P0 | Active decisions are obstructed by other workspaces. | At 1280 x 720, the AI and Fleet drawers cover the right side of the decision card. At 1024 x 768, the left navigator covers its left side and Fleet covers its right side. | A pending decision should enter a dedicated focus layout. Side panes must reflow, collapse or become mutually exclusive. The complete evidence and action row must always remain visible. |
| UX-02 | P0 | Mission-critical status disappears at compact width. | The `max-width: 1050px` rule hides `.top-bar__status-line`, removing Link, Auto, GNSS, track/readiness and queue state. | Keep a compact critical-status strip at every supported viewport. Less important workspace navigation may collapse into a menu; link, positioning, authority and queued-command state must not disappear. |
| UX-03 | P0 | The screen shows conflicting or ambiguously scoped safety state. | The header showed `GNSS DEGRADED` while the map card showed `GNSS-DENIED`. The decision simultaneously showed `Within ROE`, `ROE HOLD`, `Civ buffer 0m` and an enabled Confirm action. | Every state needs a subject and scope, for example `Mission GNSS: degraded` versus `I-03 GNSS: denied`. Replace ambiguous zero values with `unknown`, `none configured` or a real measured distance. Explain exactly why an action is permitted or blocked. |
| UX-04 | P0 | Several controls imply operational effects that are not implemented. | Auto changes UI state only. ROE Publish creates a local audit entry but does not publish a backend policy. `OPTIMIZE + DISPATCH` first produces a proposal. Logs are fixture recordings. | Labels must describe the actual state transition. Hide unavailable capabilities or mark them unmistakably as simulated. Only show success after a durable backend acknowledgement. |
| UX-05 | P0 | Offline messaging contradicts command behavior. | The connection overlay says commands are read-only, while command thunks queue commands and automatically flush them on reconnection. | Display explicit states: `local draft`, `queued`, `requires revalidation`, `sent`, `acknowledged`, `executed`, `rejected` and `expired`. Never replay a high-consequence command automatically against a changed picture. |
| UX-06 | P0 | Bulk confirmation lacks an adequate aggregate review. | `Confirm all (2)` is adjacent to a single recommendation and uses a second-click pattern, but does not preview every affected track, asset, policy result and changed/stale condition. | Open an aggregate review showing all affected objects, validation results, conflicts and authority. Require revalidation immediately before submission. |
| UX-07 | P1 | Utilities can be partly unclickable over an open right panel. | In replay, the drawer is rendered inside the top-bar stacking context while the right mission panel occupies a higher sibling layer. The center of the Fleet item resolves to the underlying mission panel. | Render global dialogs/drawers through a root-level portal with a single documented overlay stack. Add a regression test for Utilities over every workspace. |
| UX-08 | P1 | The top bar mixes navigation, operating mode, technical state and global commands. | Defense/Recon/Attack, Sensors/ROE/AI/Logs, deployment mode, link health, autonomy and Hold/Recall are presented as one dense row. | Separate mission context, workspace navigation, critical status and global commands into distinct regions. Changing a mission profile should not look equivalent to opening Logs. |
| UX-09 | P1 | High-consequence global commands are underspecified. | `Hold all tasking?` says that pending recommendations remain and no new auto-engage occurs, but does not explain the effect on assigned, moving or engaged assets. The dialog has no accessible name. | Show scope, affected asset count, current actions, exceptions and resulting state. Label the dialog and manage initial focus, focus trap, Escape and focus return. |
| UX-10 | P1 | The active decision persists beneath unrelated specialist workspaces. | The decision card remains actionable while AI or Fleet is open, but portions of it are clipped. | Either keep a compact non-actionable decision alert with a `Return to decision` action, or switch to a full decision workspace. Do not leave partially usable commands underneath another task. |
| UX-11 | P1 | Demo state is visually indistinguishable from live truth. | The application starts with active threats, assets, recommendations and operational language. Replay missions look like a real archive. | Introduce explicit `LIVE`, `TRAINING`, `SIMULATION` and `REPLAY` environment treatments, with persistent watermark/status and separate data stores. |
| UX-12 | P1 | Mission planning is represented by a production-looking placeholder. | The Missions tab says `Reserved workspace` and describes future behavior while also showing active and pending counts. | Hide it from operational navigation until usable, or replace it with the structured Brief/plan/approval workflow. |
| UX-13 | P1 | Disabled and unfinished tools add visual noise without explanation. | Tools mixes working functions with disabled Area, Coverage, Route, Relay, Geofence, Report and GRG actions. | Group unavailable tools under `Planned capabilities`, provide a reason, or remove them from the operational build. |
| UX-14 | P1 | Raw technical errors are exposed as operator feedback. | Fleet Manager displays `fetch failed`; simulator status and action availability can visually disagree. | Translate failures into operator language: affected capability, operational impact, last known state and recovery action. |
| UX-15 | P1 | Ranking is difficult to interpret under time pressure. | The top match can be only 33%, while confidence is 94%, response and cost scores are zero, and the card still appears strongly selected. | Name each metric explicitly: `track confidence`, `asset suitability`, `response contribution`, `relative cost`. Explain low total fit and show blocking/degrading factors first. |
| UX-16 | P1 | The map is overloaded by multiple independent panes. | Field Navigator, terrain/GNSS status, decision card, map controls, legend and ranked inspector compete for the same map area. | Establish an occlusion budget. Permit one primary side pane and one compact contextual card; move secondary analysis into tabs or a dedicated workspace. |
| UX-17 | P1 | Replay looks operational but is not backed by live recordings. | The archive contains three static frontend fixtures. | Label current content `Sample replay`, then replace it with event-ledger recordings including source, operator, timestamp, communication gaps and policy version. |
| UX-18 | P2 | Text and controls are too small for rapid or touch operation. | At 1280 x 720, 33 visible controls were below 32 px high or 44 px wide. Many labels use 8–10 px type. | Use at least 12 px for persistent operational metadata, 14 px for primary content, and 36–44 px control height depending on target device. |
| UX-19 | P2 | Low contrast is widespread. | An automated approximation found 35 visible low-contrast text candidates. Repeated 9 px muted labels measured around a 2.8:1 contrast ratio on their solid panel background. | Raise muted-text contrast and verify WCAG contrast on solid and translucent/map backgrounds. Do not rely on color alone for state. |
| UX-20 | P2 | Several form controls lack useful accessible names. | ROE action-permission comboboxes expose no action-specific accessible label. The Hold/Recall dialog lacks `aria-labelledby` or an equivalent name. | Associate every control with the object/action it changes and add accessible dialog naming and descriptions. |
| UX-21 | P2 | Search is shown where it does not apply. | `Find objects in the field` remains visible on Tools and the placeholder Missions tab. | Make search contextual to Overview, or change its scope and placeholder with the selected tab. |
| UX-22 | P2 | Sensor health is comprehensive but not prioritized. | Source administration, runtime sensor creation, detailed history and operational freshness appear in one long workspace. | Default to operational impact and stale/degraded sources. Move creation and integration diagnostics into an engineering/admin view. |
| UX-23 | P2 | Map rendering warnings undermine confidence and may degrade visuals. | Console warnings report missing map sprites and reuse of the terrain source for hillshade and 3D terrain. | Package required sprites and use separate sources/configuration for terrain and hillshade. Treat a clean console as a release gate. |
| UX-24 | P2 | Workspace return paths are inconsistent. | AI uses `Battlespace`, Fleet uses `MAP`, Logs uses `Live map`, while Sensors and ROE toggle from the top bar. | Standardize workspace navigation, browser-history behavior and the label for returning to the operational picture. |

## Information architecture recommendation

The current shell should be reorganized around operator intent rather than component ownership.

### Persistent command strip

- current mission, environment and mission state;
- link/PACE status and last synchronization;
- position/navigation integrity;
- active policy version and operator authority;
- pending, stale and queued command counts;
- UTC/Zulu time.

These items must survive every supported breakpoint.

### Primary workspaces

1. **Operate** — common operational picture, reports, tasks and current decisions.
2. **Plan** — commander intent/Brief, mission phases, constraints, resource allocation and validation.
3. **Assets** — readiness, assignments, payload, communications and robotic-platform supervision.
4. **Sensors** — fused-source quality for operators; detailed diagnostics for technical roles.
5. **Policy** — versioned ROE/authority configuration, review and publication.
6. **Review** — durable event replay, decisions, communications gaps and after-action analysis.

AI should remain an advisory drawer or sidecar attached to the current workspace, not a peer operating mode.

## Command interaction model

Every operational command should show the same state machine:

```text
Draft -> Validated -> Submitted -> Received -> Accepted -> Executing -> Complete
                    \-> Revalidation required
                    \-> Rejected / Expired / Superseded
```

Each state should carry:

- command identifier and version;
- issuing operator and authority;
- affected mission/assets;
- policy version;
- source-picture version and age;
- sent, received and acknowledged timestamps;
- reason for rejection, expiry or required revalidation.

## Responsive acceptance matrix

| Viewport | Required behavior |
|---|---|
| 1920 x 1080 | Map, one side pane and decision focus may coexist without overlap. |
| 1366 x 768 | All critical status and complete decision actions remain visible. Secondary panes collapse. |
| 1280 x 720 | Same as 1366; this is the current practical minimum desktop target. |
| 1024 x 768 | Use a single-pane or bottom-sheet layout. Never hide link, GNSS, policy, authority or queue state. |
| Below 760 px | Explicitly unsupported for command use, or provide a purpose-built read-only/mobile view. |

Test every viewport with:

- left navigator open and collapsed;
- ranked inspector open and closed;
- pending decision and no pending decision;
- Utilities over Operate, Fleet and Review;
- disconnected, reconnecting, degraded GNSS and stale-picture states;
- keyboard-only operation and 200% zoom.

## Remediation roadmap

### Phase 0 — shell and safety truthfulness

1. Fix overlay stacking with a root portal and documented z-index tokens.
2. Replace free-floating decision placement with responsive focus layout.
3. Preserve critical status below 1050 px.
4. Scope GNSS, link, ROE and authority labels to the relevant mission/asset/action.
5. Rename controls to match actual behavior and label simulated/sample content.
6. Add accessible dialog names, focus management and action-specific form labels.
7. Remove or quarantine unfinished tools and the Missions placeholder.
8. Fix map warnings and raw `fetch failed` feedback.

### Phase 1 — governed mission workflow

1. Add structured commander intent/Brief and mission amendments.
2. Introduce policy versions and backend publication.
3. Split plan, validate, approve and execute into explicit states.
4. Add sent/received/accepted/rejected command receipts.
5. Replace automatic offline replay with expiry and revalidation.
6. Add source, freshness, confidence and staleness to all COP objects.

### Phase 2 — real BMS completeness

1. Persist the operational domain and event ledger.
2. Generate replay from real events rather than frontend fixtures.
3. Add tactical messages, reports, overlays, unit hierarchy and acknowledgements.
4. Add roles, delegated authority and multi-operator conflict handling.
5. Implement standards-based symbology and exchange interfaces.
6. Conduct DDIL, out-of-order event, failover, restore and load testing.

## Phase 0 implementation acceptance criteria

- No primary action or decision evidence is clipped at 1024 x 768 or larger.
- Opening Fleet, AI, Review or Utilities cannot leave a partially actionable decision underneath.
- Link, navigation integrity, policy/authority and queue state remain visible at all supported widths.
- Utilities items are clickable over every workspace.
- No operational label claims a backend effect without a durable acknowledgement.
- Offline commands never auto-execute after reconnection without freshness and policy revalidation.
- All dialogs have accessible names and keyboard focus returns to the trigger.
- All visible operational text meets the chosen contrast target and no persistent text is below 11–12 px.
- Console contains no missing-sprite, source-reuse or uncaught application warnings.
- Simulation and sample replay are continuously distinguishable from live operation.
