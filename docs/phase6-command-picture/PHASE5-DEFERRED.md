## Required mission-menu positioning correction

The candidate-8 complete browser run exposed a different inherited defect: an
asynchronously loaded saved-scenario catalogue can push an already-open submenu's
anchor out of the parent scroll area. In the controlled 18-row reproduction, the
Developer fixtures trigger moved to y=1020 and Tactical to y=984 in a 900px viewport;
ordinary pointer activation timed out. The unchanged Radix partial-sticky limiter
kept the floating submenu attached to the offscreen anchor.

Candidate 9 uses Radix `sticky="always"` on the two mission submenus. The same
probe now places Tactical at y=864–896 and activates it successfully. A browser
regression delays the real saved-catalogue response until the submenu is open,
then checks actual hit testing and ordinary pointer selection. No fixture, resolver,
validation, simulation or timeout changes are involved. Independent review and the
complete final browser gate cover this narrow correction separately from Phase 5
closure.
