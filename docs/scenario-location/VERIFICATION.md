## Method

Author UI checks used **foreground Microsoft Edge 153.0.4234.46**, a new context for each run, 1440 × 900 CSS viewport, and explicit narrow checks at 760/820/900 × 900. The author inspected screenshots, committed world positions and read-only renderer diagnostics. First-party scenario APIs seed reusable fixtures; actual UI controls perform authoring, validation and Run. Each helper owns one backend and one separate SQLite database. No operator browser profile or storage is used.

Blank-provider builds isolate application behavior. The configured Tactical check uses the existing regional pack and canonical assets; it made **zero external provider requests**. These are functional/camera/resource checks, not a new FPS benchmark. The motion clip samples screenshots for approximately 12 seconds and encodes them at the observed average sampling rate; it cannot establish display FPS or frame pacing.

## Limits and failures retained honestly

Initial author harness failures were corrected: checking a scrollable Cancel button without keyboard scrolling; ambiguous pane selector; expecting synchronous End acknowledgement; assuming saved action array order; and expecting a replay-only badge on an ended recording. The product has **no timeline/replay UI**; the supported recorded-inspection workflow is Previous demos. Intermediate evidence/logs are retained in the external archive alongside final passing results. No screenshot alone is claimed as proof of movement.

The initial existing-browser run also exposed an outdated boundary-test setup that expanded a category without selecting a profile. The helper now explicitly chooses the already-supported Quadcopter profile, consistent with the baseline UI. No behavioral assertions were removed. New authoring wire-version assertions were updated to 1.6 with explicit geometry assertions; archived legacy validation is tested separately.

No universal geographic/provider-coverage claim is made. Polar/date-line footprints are rejected. Global hosted imagery/terrain/Google photorealistic coverage at every supported origin has not been surveyed. The existing loaded-Video FPS limit, occasional ordinary-3D cold startup and dense ordinary-3D label overlap remain outside this feature. No new combat semantics, global-area simulation, relocation or terrain-height rebasing was introduced.
