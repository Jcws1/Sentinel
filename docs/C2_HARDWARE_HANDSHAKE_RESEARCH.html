Technical research brief · Sentinel

The hardware handshake between drones, sensors and C2.

A C2 platform does not connect directly to “a drone.” It connects to a protocol endpoint through radios, modems, edge compute and an adapter that turns device-specific messages into a trusted operational model.

00 / THESIS

The edge adapter is the handshake.

The radio creates a path. MAVLink or a vendor protocol creates a conversation. The edge adapter decides whether that conversation represents a known, healthy and commandable asset.

→

Sentinel should never connect its UI directly to a flight controller.

The edge adapter owns serial and network connections, discovery, durable identity, time synchronization, capability checks, retries, command acknowledgements, recording and link-loss behavior. The UI sees a normalized vehicle and requests authorized mission actions.

02 / HARDWARE

Two viable hardware stacks.

A bench MVP can connect a flight controller directly to a ground radio. A fieldable system normally adds a Linux mission computer and an IP data link.

UAV

On the vehicle

  • Pixhawk-class flight controller
  • PX4 or ArduPilot flight stack
  • GNSS, IMU, compass and battery monitor
  • Air-side MAVLink telemetry radio
  • Manual RC and configured link-loss failsafe
GND

On the ground

  • Matching telemetry-radio endpoint
  • USB, serial or Ethernet connection
  • Laptop or small edge computer
  • MAVLink Router and Sentinel adapter
  • Independent pilot/GCS fallback during testing
AIR

Air segment

  • Safety-critical flight controller
  • Linux mission or companion computer
  • MAVLink or DDS over serial/Ethernet
  • IP radio, LTE or tactical mesh modem
  • Payload controller and video encoder
EDGE

Ground segment

  • Ground modem or mesh-network endpoint
  • Rugged edge computer and network switch
  • Encrypted tunnel and device credentials
  • Containerized vehicle/sensor adapters
  • Local cache, recorder and store-and-forward
03 / MAVLINK

The seven-stage vehicle handshake.

“Connected” is not one event. Sentinel should expose connection state as a progression from transport availability to authenticated command authority.

Link establishment

Pair the transport first.

The radio, LTE modem, Wi-Fi or wired network establishes connectivity. This is outside MAVLink. The adapter then opens a serial, UDP or TCP endpoint.

COM @ baudUDP :14550TCP/IP
Discovery

Listen for heartbeat.

The autopilot broadcasts its system ID, component ID, vehicle type, autopilot type, mode and state. Missing expected heartbeats is the first link-loss signal.

HEARTBEATsysidcompidMAV_STATE
Identity

Bind protocol identity to asset identity.

A numeric MAVLink system ID is not an enterprise identity. Bind hardware UID, expected firmware, provisioned key and Sentinel vehicle ID in the edge registry.

AUTOPILOT_VERSIONuid / uid2allow-list
Negotiation

Discover versions and capabilities.

The adapter verifies MAVLink 2 and asks what mission, command, parameter, file, camera, gimbal and metadata services are actually supported.

MAV_CMD_REQUEST_MESSAGECOMPONENT_METADATAcapabilities
Synchronization

Align clocks and initial state.

Estimate clock offset and link latency, then acquire position, attitude, velocity, home, battery, estimator health, mission and payload state.

TIMESYNCGLOBAL_POSITION_INTBATTERY_STATUS
Readiness gate

Separate visible from commandable.

The adapter may display a vehicle while withholding command authority because its signature, firmware, position estimate, operator ownership or configuration is unacceptable.

telemetry_readycommandable=falsereason[]

Translate intent and require acknowledgement.

Sentinel sends an authorized mission action. The adapter emits an addressed MAVLink command or mission transaction and maps acknowledgements, progress, rejection and timeout back to the original command ID.

04 / SENSORS

Sensors use the same pattern, not necessarily MAVLink.

The southbound protocol changes; the edge responsibilities do not. Radar may use ASTERIX or a vendor stream, cameras may use ONVIF/RTSP, and modern counter-UAS nodes may expose SAPIENT.

IN

Southbound inputs

  • Ethernet, serial, CAN, USB or radio receiver
  • SAPIENT, ASTERIX, ONVIF/RTSP or vendor SDK
  • Sensor identity, pose and configuration revision
  • Detections, local tracks, status and evidence
  • Optional look-at, mode and report-rate tasking
OUT

Northbound output

  • Authenticated source registration
  • Normalized measurement and coordinate frame
  • Observed-at and gateway-received timestamps
  • Confidence, covariance and provenance
  • Task acknowledgements and health lifecycle
05 / TRUST

Protocol connectivity is not operational trust.

A valid packet proves very little by itself. Authentication, confidentiality, durable identity and command authority must be explicit system services.

MAVLink signing authenticates; it does not encrypt.

MAVLink 2 signatures can verify that a message came from a holder of the shared key and provide replay protection. The telemetry content remains readable unless the radio or IP transport is encrypted separately.

A heartbeat must never grant command authority.

Require an allow-listed device identity, valid credentials, approved firmware/capabilities, healthy navigation state and explicit control ownership before the adapter accepts C2 commands.

10 / BENCH

Minimum proof before a flight test.

Prove the complete handshake on a propeller-free bench before connecting Sentinel to an armed or flight-capable platform.

Hardware

  • Flight controller powered safely
  • Air/ground radios paired
  • Stable serial or UDP endpoint
  • Independent manual-stop path
  • No propellers installed

Handshake

  • Unique identity binding
  • MAVLink 2 negotiated
  • Time offset measured
  • Health telemetry validated
  • Link-loss state verified

Commands

  • Authority gate defaults closed
  • Every command has an ID
  • ACK/reject/timeout displayed
  • Duplicate command is safe
  • Record/replay captures lifecycle
