# Recovery and authority verification

D7 uses separate databases and fresh browser contexts. A test result establishes the named boundary; it is not evidence that every possible timing/interleaving is covered. Raw paths below are relative to the D7 [external archive](../ARCHIVE.md).

| Run uncertainty / exact revision | `browser/scenarios.spec.ts` and `d3a.spec.ts` submit through real UI, deliberately lose committed responses, reconcile/retry and assert one Run, immutable revision and action ordering. Foreground authoring executes exact saved r2 and later edits cannot change paused frozen geometry. |

| Other transaction boundaries | `test_interactive.py`, `test_scenarios.py`, `test_movement.py`, `test_d3a.py` and `test_recommendations.py` inject failure at frames, checkpoints, events, run artifacts, scenario revisions and receipt/audit persistence. They assert no adoption/publication/partial identity and preserved old bytes. These are isolated backend tests, not all foreground demos. |

The fault server is **test-only** `backend/tests/integrated_runtime.py`. It requires explicit opt-in and a `verification-*.sqlite3` file directly under `frontend/.cache`; normal app routes contain no probe endpoints. Tests check the opt-in/path guard before database creation. It patches only its task process and retains the original source loop, writer, transactions, simulation clock and production command admission.

Intermediate runner errors are retained: the storage failure is intentionally503 rather than500; nonpositional policy/Stop controls are allowed during source delay; a closed Suggestions disclosure needed opening for a role query; successful recovery removes the attention element rather than leaving empty text. The final assertions match those existing contracts. No production simulation rule was changed to make these checks pass.
